# D28: Attempts

## Status

Accepted. PRD 1, decision D28.

## Context

A task can need more than one sandbox: after a stop, after an approval, or after an answer of the owner. The turn that was lost in a stop runs again. Its rows must not replace the rows of the first run, and must not be lost.

## Decision

- Each start of a sandbox for a task is a new attempt with the next number.
- The attempt number is in the pass, in each trail row and in each cost row.
- A pass opens only its own attempt. A call with the pass of an old attempt is refused.
- A new attempt is added only if no attempt row has its cause, so a report that comes two times adds one attempt.

## Consequences

- The rows of a turn that runs again stay beside the rows of the first run, with a different attempt number.
- A model call that runs again is a real cost, and it has its own cost row.
- The current attempt of a task is the largest attempt number. No column stores it.

## Alternatives Considered

- One sandbox for each task with no attempt number: the rows of a turn that runs again would collide with the first rows, or replace them.
- Delete the rows of a lost turn: the trail would hide work that really ran and cost money.
