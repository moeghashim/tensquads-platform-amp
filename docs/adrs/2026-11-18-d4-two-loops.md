# D4: Two Loops In Two Places

## Status

Accepted. PRD 1, decision D4.

## Context

Petra must always be on, and she handles the commands of one account one at a time. A bot reads text from strangers and runs tools, so it must run in an isolated place that keeps nothing after it stops.

## Decision

- Petra and her own loop run on Cloudflare, in one Durable Object for each account. The name of the object is the account id.
- The agent loop of each bot runs in a sandbox, one sandbox for each attempt of a task. The sandbox is on boat.dev.
- In this build, `apps/launcher` starts `apps/runner` as a local process. It stands in for boat.dev.

## Consequences

- Petra never starts a process. She asks for a sandbox through the sandbox port (requirement L12).
- A later real adapter of the sandbox port calls boat.dev, and the launcher is removed. No other part changes.

## Alternatives Considered

- Run the loop of a bot in the Durable Object of Petra: a bot would run next to the keys and the writer of the account.
- One long sandbox for each account: a task would not start from an empty place, and a fault in one task could change the next one.
